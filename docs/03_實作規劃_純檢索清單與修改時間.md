# SFTP 批次工具 — 「純檢索產出清單」與「檔案修改時間/副檔名」詳細實作規劃

## 1. 需求背景與設計目標

在先前的版本中，工具具備了「動態純目錄階層自適應」與「最後目錄目標檔案過濾下載」的能力，並在下載結束後自動生成包含下載狀態的 Manifest CSV 報表。
根據最新需求，本階段將擴充以下兩大核心能力：
1. **清單資訊豐富化**：
   - 在生成的 CSV 報表中新增「**檔案修改時間**」（遠端 Unix mtime 轉換為 `YYYY-MM-DD HH:MM:SS`）與「**副檔名**」（如 `.csv`、`.txt`），讓使用者直接掌握檔案的時間狀態與型態。
2. **「僅搜尋並產出清單 (不下載檔案)」模式 (Scan-Only / Dry-Run)**：
   - 使用者貼上目錄清單後，可以只對遠端目錄做快速檢索與盤點，不進行任何實體二進位檔案下載傳輸。
   - 毫秒～秒級完成成百上千個檔案的走訪與統計。
   - 自動產出完整 Excel/CSV 清冊，包含：所屬各層目錄、檔名、副檔名、檔案大小、檔案修改時間、遠端完整路徑、以及**空目錄/不存在目錄之警示標記**。
   - 介面提供一鍵直接以 Excel 開啟檢視。

## 2. 系統架構與資料流變更 (Dataflow Architecture)

```
[使用者點擊] -> [🔍 僅搜尋與產出清單] 
                     │
                     ▼
         [Connection / Settings 驗證]
                     │ (通過)
                     ▼
  [DownloadWorker(scan_only=True)] (背景執行緒)
                     │
                     ├─> [SFTPManager.connect()]
                     │
                     ├─> [TraverseEngine.scan_all()]
                     │     ├─ 遞迴走訪各層目錄 (帶實體目錄 Listing 快取)
                     │     ├─ 在最後一層目錄匹配目標檔案 (如 *.csv 或 全選)
                     │     ├─ 記錄空目錄 (Empty Dir) 與不存在目錄 (Not Found)
                     │     └─ 收集每個檔案的 st_mtime 與 st_size
                     │
                     ├─> [DownloadManager.generate_scan_manifest_csv()]
                     │     ├─ 將 tasks 與空目錄轉換為 ReportRecord
                     │     ├─ 計算檔案副檔名 (file_ext) 與 易讀時間 (mtime_str)
                     │     └─ 產出 UTF-8-SIG CSV 檔案 (清單_YYYYMMDD_HHMMSS.csv)
                     │
                     ▼
            [UIEvent(SCAN_FINISHED)]
                     │
                     ▼
  [MainWindow] 80ms 輪詢更新：
   - 顯示「檢索完成！掃描 N 個目錄，找到 M 個檔案，總容量 X」
   - 解鎖 [📑 開啟下載清單 (Excel)] 按鈕，記錄最新清單路徑
   - 恢復按鈕狀態
```

## 3. 模組具體實作規劃

### 3.1 資料模型層 (`models/data_models.py`)

#### 變更點 1：擴充 `TransferStatus(Enum)`
新增下列狀態枚舉：
- `INDEXED = "已檢索 (未下載)"`：代表在純檢索模式下成功找到該檔案。
- `EMPTY_DIR = "空目錄 (無相符檔案)"`：代表終端目錄存在，但無符合過濾條件的檔案。
- `DIR_NOT_FOUND = "目錄不存在"`：代表遠端未找到該目錄。

#### 變更點 2：擴充 `ReportRecord`
- 新增屬性 `file_mtime: int = 0`（遠端時間戳記）。
- 新增計算屬性 `mtime_str -> str`：
  ```python
  @property
  def mtime_str(self) -> str:
      if self.file_mtime <= 0:
          return ""
      try:
          return datetime.datetime.fromtimestamp(self.file_mtime).strftime("%Y-%m-%d %H:%M:%S")
      except Exception:
          return ""
  ```
- 新增計算屬性 `file_ext -> str`：
  ```python
  @property
  def file_ext(self) -> str:
      if not self.filename:
          return ""
      _, ext = os.path.splitext(self.filename)
      return ext.lower()
  ```

---

### 3.2 下載管理員與清單生成器 (`core/download_manager.py`)

#### 變更點 1：`generate_manifest_csv` 欄位擴充
將輸出表頭更新為完整的 12 大維度：
1. `序號`
2. `第 1 層目錄` ... `第 N 層目錄` (動態展開)
3. `檔案名稱`
4. `副檔名`
5. `檔案大小 (Bytes)`
6. `檔案大小 (易讀)`
7. `檔案修改時間`
8. `處理狀態` (如：下載成功、已略過、已檢索 (未下載)、空目錄 (無檔案)、目錄不存在)
9. `處理說明`
10. `遠端完整路徑`
11. `本地完整路徑` (純搜尋模式下為本地預計儲存路徑)
12. `完成時間` (報表產出時間)

#### 變更點 2：提供快速封裝方法 `generate_scan_manifest_csv`
接收 `List[RemoteFileTask]` 以及未找到檔案的目錄清單，直接批次封裝為 `ReportRecord(status=TransferStatus.INDEXED)`，並呼叫 CSV 寫入邏輯。

---

### 3.3 目錄走訪引擎 (`core/traverse_engine.py`)

#### 變更點 1：記錄空目錄與未匹配目錄
在目前的遍歷邏輯中，若某條規則在推進到最後一層時：
- 終端實體目錄存在，但目錄下沒有任何檔案符合過濾條件（例如全是空目錄或只有其他副檔名的檔案）：
  - 記錄一個空檔案任務，便於在純檢索報表中輸出 `[空目錄 (無相符檔案)]`。
- 若遠端根本找不到該目錄：
  - 記錄為 `[目錄不存在]`。
這樣使用者能明確得知每筆目錄的實際走訪結果。

---

### 3.4 背景工作執行緒 (`core/worker.py`)

#### 變更點 1：`DownloadWorker` 支援 `scan_only: bool = False`
- 初始化時傳入 `scan_only: bool`。
- 在 `run()` 流程中：
  - 建立 SFTP 連線。
  - 執行 `TraverseEngine.scan_all()` 走訪。
  - 若 `scan_only == True`：
    - 跳過逐檔 `download_file` 迴圈。
    - 計算總檔案數與總容量大小。
    - 呼叫 `generate_scan_manifest_csv()` 產出報表。
    - 發送 `UIEvent(UIEventType.FINISHED, "檢索完成！共發現 {count} 個檔案 ({total_size})，清單已生成。")`。
  - 若 `scan_only == False`：維持既有下載流程。

---

### 3.5 主視窗 UI (`ui/main_window.py`)

#### 變更點 1：新增按鈕與佈局調整
在底部控制按鈕列中：
- 佈局順序：
  - `[🔍 僅搜尋與產出清單]` (綠色/藍綠色強調色)
  - `[▶ 開始搜尋與下載]` (深青色/藍色)
  - `[⏹ 停止]` (紅色)
  - `[📑 開啟下載清單 (Excel)]` (深色/有檔案時綠色高亮)
  - `[📁 開啟下載資料夾]`
- 當使用者點擊 `[🔍 僅搜尋與產出清單]`：
  - 執行表單欄位驗證（檢查主機、帳號、密碼、目錄規則）。
  - 將控制項設為禁用狀態（防重複點擊），停止按鈕設為啟用。
  - 啟動 `DownloadWorker(..., scan_only=True)`。

#### 變更點 2：事件迴圈與報表聯動
- 當收到背景檢索完成事件時：
  - 狀態列與記錄區更新：`[成功] 檢索完成！共發現 X 個檔案 (總大小 Y)，清單已自動生成。`
  - 記錄產出的 CSV 路徑至 `self._latest_manifest_path`。
  - 立即啟用 `[📑 開啟下載清單 (Excel)]`，使用者點擊即可透過系統預設程式開啟 Excel 檢視。

## 4. 提出給使用者討論的關鍵設計細節 (Questions for Discussion)

在開始編寫代碼前，特別提出以下 3 個細節與您確認討論：

### 討論點 1：產出的清單檔案命名原則
- **方案 A (統一前綴)**：無論純搜尋還是實際下載，檔名均以 `下載清單_YYYYMMDD_HHMMSS.csv`（或 `檔案清單_YYYYMMDD_HHMMSS.csv`）命名。好處是使用者認知統一，按鈕一鍵開啟永遠指向最新一份。
- **方案 B (嚴格區分前綴)**：純搜尋命名為 `檢索清單_YYYYMMDD_HHMMSS.csv`，下載命名為 `下載清單_YYYYMMDD_HHMMSS.csv`。介面上的按鈕會自動記錄並開啟最新產生的那一份。
> **建議**：採用方案 B，前綴精準表達該檔案是「純檢索」還是「下載實績」，介面按鈕均可自動追蹤並一鍵開啟。

### 討論點 2：純搜尋模式下的本地儲存路徑
- 在純搜尋模式下，不需要下載檔案，但產出的 CSV 報表需要存放在本地端。
- 目前本地端已有「本地儲存路徑」欄位（預設通常為 Downloads 或工具預設目錄）：
  - 產出的 CSV 依然存放在「本地儲存路徑」中，若使用者未填寫則預設存在工具同層目錄下。
  - 這樣一來，點選「開啟下載資料夾」或「開啟下載清單 (Excel)」都能順暢運作。

### 討論點 3：是否需要在介面即時表格上預覽找到的檔案？
- **方式 A (直接開啟 Excel)**：介面上的主表格依然專注維持「使用者貼上的目錄規則」，找到的成百上千個檔案直接由產出的 Excel 開啟瀏覽（因為 Excel 具備強大的搜尋、排序、篩選功能，適合處理大量檔案）。
- **方式 B (介面動態切換檢視)**：介面提供分頁或切換按鈕，切換看「目錄規則」或「搜尋到的檔案列表」。
> **建議**：建議採用方式 A（直接產出並透過 `[📑 開啟下載清單 (Excel)]` 檢視）。因為使用者處理的目錄與檔案量可能高達數千甚至上萬筆，直接交給專業的 Excel 進行篩選與統計最為流暢，UI 也不會因為渲染幾萬筆資料而卡頓。
