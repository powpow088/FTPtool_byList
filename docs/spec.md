# SFTP 批次檔案檢索與結構保留下載工具 — 系統規格書 (System Specification)

## 1. 系統概述與目標

本工具為一套具備現代化圖形介面 (GUI) 的桌面應用程式，主要解決使用者在 SFTP 伺服器上需要跨多層目錄、透過模糊關鍵字與萬用字元（如 `*RAW*`）批次定位並下載目標檔案的問題。
特別針對使用者由 Excel 整理與複製貼上清單的操作習慣進行深度優化，支援：
1. **Excel 貼上資料 100% 為純資料夾層級**（貼上 $N$ 欄即為 $N$ 層目錄，支援動態自動適配欄位）。
2. **在最後一層目錄底下精準匹配目標檔案**：由下方的「目標檔案過濾」輸入框（如 `*RAW*`、`*RAW*-*.csv`）指定過濾條件。
3. **比對模式自由切換（預設「模糊包含」，可切換「完全精準相符」）**。
4. **「遠端路徑瀏覽器 [瀏覽遠端...]」**：免記遠端複雜 Linux 路徑，點選資料夾直接帶入。
5. **本地目錄樹鏡像結構保留**：`LocalRoot/Dir1/Dir2/.../FileName`。
6. **本地端自動生成「完整下載清單 CSV (10 大欄位)」**，並提供一鍵開啟。
7. **100% 免疫 Windows 11 Smart App Control (SAC) 安全阻擋**。

## 2. 技術選型與依賴環境

- **開發語言**：Python 3.10+
- **GUI 框架**：`CustomTkinter` + `tkinter.ttk`（純 Python 現代化暗黑/淺色高質感控制項、高解析度 DPI 支援、微軟官方簽署底層，100% 免疫 Windows 11 Smart App Control 攔截）
- **SFTP / SSH 連線套件**：`paramiko`（支援標準 SFTP 協定、逾時設定、Keep-Alive 與連線維護）
- **萬用字元匹配**：Python 內建 `fnmatch`（支援標準 Glob 模式與大小寫不敏感比對）
- **資料與設定持久化**：標準庫 `json`（連線設定、歷史紀錄、介面狀態儲存）
- **報表匯出**：標準庫 `csv`（使用 `utf-8-sig` 編碼，Excel 開啟不亂碼）
- **Excel 檔案讀取**：`openpyxl`（支援直接匯入 `.xlsx` 規則清單）

## 3. 詳細功能與模組規格

### 3.1 SFTP 連線管理與「遠端路徑瀏覽器」模組
1. **連線設定區配置 (Row 1 & Row 2)**：
   - **第一列 (Row 1)**：
     - `主機 (Host)`、`Port` (預設 22)、`帳號 (Username)`、`密碼 (Password)` (密碼遮罩附帶眼睛按鈕切換顯示)。
     - **帳號與密碼緊鄰排列**，完全符合一般登入表單操作直覺。
   - **第二列 (Row 2)**：
     - `遠端初始路徑` (預設 `/`，自動校正補齊開頭 `/`)。
     - **`[瀏覽遠端...]` 按鈕**：呼叫「遠端目錄瀏覽器 (RemoteBrowserDialog)」。
     - `記住連線資訊` 核取方塊。
     - `[測試連線]` 按鈕。
2. **遠端路徑瀏覽器視窗 (RemoteBrowserDialog)**：
   - 點選 `[瀏覽遠端...]` 後，透過背景連線讀取遠端目錄清單。
   - 提供視窗瀏覽遠端資料夾：
     - 上方顯示「目前路徑」，並有「⬆ 回上一層」與「🔄 重新整理」按鈕。
     - 中間以清單列出該層所有純資料夾（排除一般檔案）。
     - 雙擊資料夾即可進入下一層。
     - 下方「選擇此目錄」按鈕：確認後自動將所選完整路徑填回主視窗之「遠端初始路徑」！
     - 下方「取消」按鈕：關閉視窗。

### 3.2 動態純目錄階層結構與目標檔案過濾引擎 (TraverseEngine)

1. **純目錄階層動態自動適配**：
   - 使用者由 Excel 複製貼上的資料，**所有欄位皆為資料夾層級**：
     - 貼上 1 欄：自動設為 `[第 1 層目錄]`
     - 貼上 2 欄：自動設為 `[第 1 層目錄]`、`[第 2 層目錄]`
     - 貼上 3 欄：自動設為 `[第 1 層目錄]`、`[第 2 層目錄]`、`[第 3 層目錄]`
     - 貼上 $N$ 欄：自動展開為 `[第 1 層目錄]`、`[第 2 層目錄]`、...、`[第 N 層目錄]`。
   - **表格內無檔案名稱欄位**，表頭文字保持簡潔俐落（例如：`第 1 層目錄`、`第 2 層目錄`）。
2. **最後一層目錄底下之目標檔案過濾**：
   - 目標檔案過濾由介面下方「目標檔案過濾」輸入框設定（如 `*RAW*` 或 `*RAW*-*.csv`）。
   - 遍歷引擎根據表格中的目錄階層，逐步推進至該列之**最後一層目錄**。
   - 在該最後一層目錄內，列出所有一般檔案，比對目標檔案過濾條件進行批次下載。
   - 留空代表全選該最後目錄下的所有檔案。
3. **目錄比對模式 (MatchMode)**：
   - **模式 A：模糊包含 (Contains) — 預設**：
     - 目錄名稱只要包含關鍵字即符合。
   - **模式 B：完全精準相符 (Exact Match)**：
     - 目錄名稱必須與關鍵字完全相同（大小寫不敏感）。
   - **萬用字元優先原則**：若目錄規則內包含 `*` 或 `?`，優先採用標準萬用字元比對。

### 3.3 本地目錄保留、純檢索模式與自動 Manifest CSV 產出

1. **多階層鏡像目錄建立**：
   - 下載時本機自動遞迴建立對應目錄樹：`LocalRoot / Dir1 / Dir2 / ... / FileName`。
2. **衝突策略**：
   - `SIZE_MTIME`：本地已存在且大小與修改時間相同（容許 1 秒誤差）則略過。
   - `OVERWRITE`：直接覆蓋。
   - `SKIP_EXISTING`：只要存在即略過。
3. **「僅搜尋並產出清單 (不下載檔案)」模式 (Scan-Only)**：
   - 走訪遠端目錄階層並進行檔案過濾匹配，不執行實體檔案傳輸與本地目錄寫入。
   - 支援空目錄 (`EMPTY_DIR`) 與不存在目錄 (`DIR_NOT_FOUND`) 狀態標記，讓使用者在 Excel 報表中一目了然各目錄狀況。
   - 統計總搜尋目錄數、符合檔案數與總容量，快速產出清單。
4. **本地自動產出 Manifest CSV 報表**：
   - 任務完成時（包含下載完成或純檢索完成），自動於本地下載目錄生成 `下載清單_YYYYMMDD_HHMMSS.csv` 或 `檢索清單_YYYYMMDD_HHMMSS.csv`。
   - 採用 `utf-8-sig` 編碼，Excel 雙擊開啟不亂碼。
   - 欄位包含（採用方案 A 成對欄位法，每一層目錄緊鄰對應搜尋字）：
     - **下載清單**：序號, 第 1 層目錄, 第 1 層搜尋字, 第 2 層目錄, 第 2 層搜尋字, ..., 檔案名稱, 副檔名, 檔案大小 (Bytes), 檔案大小 (易讀), 檔案修改時間,  處理狀態, 處理說明, 遠端完整路徑, **本地完整路徑**, 完成時間。
     - **檢索清單 (純搜尋)**：序號, 第 1 層目錄, 第 1 層搜尋字, 第 2 層目錄, 第 2 層搜尋字, ..., 檔案名稱, 副檔名, 檔案大小 (Bytes), 檔案大小 (易讀), 檔案修改時間, 處理狀態, 處理說明, 遠端完整路徑, 完成時間（**排除本地完整路徑欄位**，聚焦純遠端伺服器檔案資產盤點）。
     - **成對欄位規則**：
       - 每一層實際目錄緊跟該層之原始搜尋條件關鍵字（如 `202611_Sales` 配 `2026`）。
       - 若該層為全選（規則未指定），搜尋字顯示為空白或留空。
       - 若遠端無相符目錄 (`DIR_NOT_FOUND`)，實際目錄為空或標示 `(目錄不存在)`，搜尋字精確填入未命中的關鍵字，利於除錯對照。
5. **雙工作表整合活頁簿產出 (下載與明細彙整 .xlsx)**：
   - 點擊「📊 彙整資料」按鈕後，自動將本地已下載之檔案穿透解析，並與下載清單合併輸出為單一 Excel 活頁簿：`下載與明細彙整_YYYYMMDD_HHMMSS.xlsx`。
   - **Sheet 1 (`下載清單`)**：收錄完整下載清單紀錄，表頭加粗、欄寬自適應。
   - **Sheet 2 (`工作表2`)**：收錄 11 大晶片明細欄位（第 1 層目錄, PN, 第 2 層目錄, LOT, RECIPE, 檔案名稱, 2D ID (MPID), X (MP_X), Y (MP_Y), MPID_X_Y, Unit BIN#）：
     - `RECIPE` (雙重保險定位)：優先以 `PN` 為錨點，尋找 `PN` 後面第一個連字號 `-` 之後的所有文字（精準解決無廠區前綴如 `3273173A-DUMMY` 之情況）；若無 PN 則依連字號數量自適應（$\ge 2$ 個取第 2 個之後，1 個取第 1 個之後）。
     - `2D ID (MPID)`、`X`、`Y`、`Unit BIN#`：自動識別前 10 列中之標題行（相容 Tab 與逗號），排除第一欄為 `Hard Limit` 之列。
     - 格式控制：A~J 欄鎖定為純文字格式 (`@`) 防止前導零遺失，K 欄為數值/文字，表頭粗體並比照原 VBA 設定欄寬（A:24, B:13, C:22, D:22, E:12, F:62, G:21, H:13, I:13, J:28, K:13）。
     - **100 萬列自動切頁機制**：單一工作表達 1,000,000 列時自動接續建立 `工作表2_2`、`工作表2_3` 等，徹底消除 Excel 1,048,576 列硬限制截斷資料之風險。
   - **完成互動**：產出完成後彈跳視窗「彙整完成！共寫入 X 筆晶片資料，是否立即開啟 Excel？」，點「是」自動呼叫 Excel 開啟。
6. **PN / LOT / RECIPE 交叉樞紐分析與權重彙整活頁簿 (彙整資料2)**：
   - 點擊「📊 彙整資料2」按鈕後，讀取 `下載與明細彙整_*.xlsx` 中的所有明細工作表（包含 `工作表2`、`工作表2_2`...）。
   - 輸出單一活頁簿：`PN_LOT_RECIPE_明細與彙整_YYYYMMDD_HHMMSS.xlsx`。
   - **Sheet 1 (`中繼明細_01`)**：
     - 固定欄：A: `PN`（若空退避 A 欄）, B: `第 2 層目錄(LOT)`, C: `LOT`（**優先直接取 D 欄 LOT**，若空退避 C 欄去尾一碼）, D: `MPID_XY`（座標補零，如 `_1_2` 轉 `_01_02`）。
     - 動態欄：所有唯一 RECIPE 橫向展開，儲存格填入 BIN 清單（逗號隔開）。若 RECIPE 空白則置於最右側 `ERROR_blank` 欄。
   - **Sheet 2 (`RECIPE彙整_01`)**：
     - 固定欄：A: `PN`, B: `第 2 層目錄(LOT)`（該 LOT 所有關聯 fullLot 逗點串接）, C: `LOT`, D: `MPID_XY`, E: `BinCode_sumary`。
     - 動態欄：各 RECIPE 欄位進行晶圓級 BIN 優先權判定（`32` > `1` > `others`）。
     - `BinCode_sumary`：整列所有正式 RECIPE 之最高優先權判定（`32` > `1` > `Others`）。`ERROR_blank` 欄排除不參與判定。
   - **分頁控制**：超過 1,000,000 列自動切頁至 `中繼明細_02` 與 `RECIPE彙整_02`。
7. **彙整效能提速與即時雙軌進度回饋機制**：
   - **寫入效能提速**：全面移除逐列單元格重複尋址之瓶頸，直接採用底層字串類型序列化保障文字格式，處理巨量晶片（數十萬至百萬筆）效能提升 5~10 倍。
   - **現有進度條情境複用**：執行「彙整資料」或「彙整資料2」時，直接重設並連動主視窗現有進度條（`self.progress_bar`，0% ~ 100% 平滑遞增）。
   - **狀態文字即時刷新**：現有狀態標籤（`self.lbl_file_prog`）即時顯示當前進度：`彙整進度: X/Y 檔 (Z%) - 累計 N 筆晶片`。
   - **中央日誌即時滾動**：每處理 5 個檔案即時輸出帶有百分比與累計晶片筆數之 `INFO` 日誌，讓使用者明確知悉處理中檔案。
   - **大檔案存檔保護日誌**：在進入 `wb.save()` 寫入硬碟前，明確輸出 `[INFO] 所有晶片資料解析完成，正在儲存 Excel 活頁簿至硬碟 (資料量較大請稍候)...`，徹底消除等待焦慮。

8. **巨量晶片資料極速引擎實作 (xlsxwriter 串流寫入 + SQLite 旁路快取 + python-calamine 退避)**：
   - **雙軌串流寫入架構 (Dual-Sink Streaming)**：
     - **彙整 1**：解析原始 CSV/TSV 同時，管道 A 使用 `xlsxwriter({'constant_memory': True})` 串流輸出 `下載與明細彙整.xlsx`；管道 B 同步寫入輕量 SQLite 旁路快取檔 `.下載與明細彙整_xxx.xlsx.cache.db`（50,000 列/批次，WAL 模式，0 額外依賴）。
     - 存檔結束後，自動將主檔案大小 `file_size` 與 `st_mtime_ns` 指紋寫入快取 `meta` 表中。
   - **智慧路由讀取引擎 (Smart Router)**：
     - **彙整 2**：優先檢查是否存在指紋吻合之 `.cache.db`，若命中則以二進位串流直接讀取（240 萬筆讀取僅需 **1.5 秒**）。
     - 若跨電腦複製僅有單一 `.xlsx`（無快取檔），自動退避使用 Rust 編譯之 `python-calamine` 解析，240 萬筆讀取僅需 **15 秒**（相較 openpyxl 之 240 秒大幅提速 16 倍）。
   - **正統半導體晶圓業務邏輯完整保全**：
     - 完整保留 `parse_recipe(level1, pn)` 之 PN 錨點解析與機台 `Hard Limit` 排除。
     - 完整落實雙層分群：`中繼明細` 依 `(pn, full_lot)` 分群；`RECIPE彙整` 依 `(pn, clean_lot)` 母批號分群（同一母批號下所有晶圓合併為同一列、B 欄 fullLot 逗號串接、跨晶圓最高權重比較）。
     - 嚴格落實 LOT 群組完整性保護與 100 萬列自動切頁（`中繼明細_01`、`RECIPE彙整_01`...），預設選中 `RECIPE彙整_01`。
   - **企業環境健壯性防禦**：
     - 整合 `sanitize_xml_text` 預先剝除 `0x00`~`0x1F` 非法控制字元，防止產出 Excel 出現損毀報錯。
     - 輸出檔案先於本機 `%TEMP%` 串流寫入，完成後透過 `safe_atomic_move` 搭配指數退避重試搬移至目標路徑，杜絕 Windows Defender / 企業防毒軟體 `WinError 32` 鎖檔干擾。
     - 批次迴圈加入 `sys.intern` 進行字串駐留，峰值記憶體穩定控制在 50 MB 以內。

9. **MS SQL 資料庫對齊整合與 PanelID / Scrapped 欄位注入 (Micro-Phase 22)**：
   - **連線庫選型與配置**：
     - 採用免安裝 ODBC 驅動、支援純 Python/FreeTDS 的 `pymssql` 連線庫。
     - 獨立連線設定檔 `core/db_config.py`，支援使用者直接填寫帳密常數，並支援 `MSSQL_HOST`、`MSSQL_USER` 等環境變數方便後端部署。
     - 若未設定資料庫資訊或連線失敗，自動降級留空並記錄警告日誌，不中斷樞紐分析報表之產出。
   - **對齊鍵值正規化 (Mapping Key Alignment)**：
     - `LotNum`：採用 D 欄母批號 `LOT`。
     - `MPID`：採用 `2D ID (MPID)`。
     - `MP_X` 與 `MP_Y`：強制轉為純整數 `int` 比對（例如 `"01"` 與 `1` 均視為 `1`）。
   - **巨量查詢效能最佳化**：
     - 彙整 2 執行前收集所有出現的母批號，以 `SELECT [LotNum], [MPID], [MP_X], [MP_Y], [PanelID], [Scrapped] FROM [dc].[dbo].[YM_ULT_UnitBase] WHERE [LotNum] IN (...)` 進行單一/分批 (500 LOT/批) 查詢。
     - 載入記憶體 Hash Map 進行 $O(1)$ 秒級 mapping。
   - **報表欄位結構調整**：
     - **`RECIPE彙整`**：固定欄位依序調整為 `[PN]` | `[第 2 層目錄(LOT)]` | `[LOT]` | `[MPID_XY]` | **`[PanelID]`** | **`[Scrapped]`** | `[BinCode_sumary]` | (各動態 RECIPE 欄位...)。
     - **`中繼明細`**：維持原始欄位結構不變（不加入 PanelID 與 Scrapped）。
     - 多筆對應處理：同一晶片在 DB 若有多筆記錄，將 PanelID 與 Scrapped 分別進行有序去重，並以純逗號 `,` 串接（如 `Panel1,Panel2`、`0,1`）。

### 3.4 精簡現代化 GUI 配置

1. **規則表格操作列**：
   - `[📋 貼上 Excel 清單 (Ctrl+V)]`、`[📂 從檔案匯入]`、`[🗑️ 清空表格]`、`比對模式: 模糊包含 / 完全精準`。
   - **新增：`[📋 複製批號 (,)]`**：位於比對模式選單右側（綠圈標記處），**採用質感綠色系外觀**（與主色調協調）。點擊自動提取表格中之有效批號（層級 >= 2 取第 2 層，單層取第 1 層），智慧排除空白列與「批號 / LOT」等標題字樣，自動進行有序去重 (Distinct)，並以純逗號（`A,B,C` 無空格）串接後直接寫入系統剪貼簿。

### 3.5 高可用連線防護、防封鎖微延遲與續傳接關機制

1. **連線健康預檢 (Pre-Flight Health Check)**：
   - 每個檔案傳輸前自動檢測 SSH Transport 與 SFTP Channel 是否存活；若發現伺服器或防火牆切斷連線，背景自動無縫執行 `reconnect()`，杜絕「單一斷線導致後續所有檔案連續秒失敗」的雪崩效應。
2. **防封鎖下載微延遲 (Gentle Pacing Delay)**：
   - 預設每次下載完成後微暫停 50ms（支援 0ms / 50ms / 150ms 切換），模擬正常使用者請求節奏，徹底避免觸發伺服器 Fail2ban / 防火牆 Rate-Limit 臨時 IP 封鎖。
3. **主動連線換氣 (Proactive Session Refresh)**：
   - 每連續下載完成 150 個檔案，主動且安全地重置連線，徹底避開伺服器／防火牆 10~15 分鐘強制連線逾時中斷與 SSH 金鑰重協商 (Rekeying) 崩潰。
4. **溫和指數退避重試 (Anti-Ban Backoff)**：
   - 網路異常斷線重試時，等待冷卻時間調整為 3 秒、6 秒、12 秒，給伺服器充足時間釋放舊連線 Session，防止瞬間連線觸發伺服器拒絕存取。
5. **接關續傳零耗能略過**：
   - 重新執行任務時，已下載且符合 `SIZE_MTIME` 的檔案在 0.001 秒內直接判定 `[續傳略過]`，不耗費頻寬直接接關下載剩餘檔案。
